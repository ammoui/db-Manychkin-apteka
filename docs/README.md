# Курс «Разработка баз данных»

За семестр вы строите одну базу данных PostgreSQL по своей теме. Каждая лаба добавляет к ней новый слой: схема, запросы, логика, транзакции, индексы. В конце курса базу нужно защитить, поверх неё делается небольшая витрина.

## Лабы

| Лаба | Тема | Что появляется в базе | Задание |
| --- | --- | --- | --- |
| 1 | Модель данных и схема | Таблицы, ключи, ограничения, тестовые данные | [lab-1.md](lab-1.md) |
| 2 | Запросы | 12 запросов к своим данным | [lab-2.md](lab-2.md) |
| 3 | Логика в базе | Представления, функции, триггеры | [lab-3.md](lab-3.md) |
| 4 | Транзакции и доступ | Гонка и её исправление, роли | [lab-4.md](lab-4.md) |
| 5 | Производительность | 100 000+ строк, индексы, планы запросов | [lab-5.md](lab-5.md) |
| | Витрина к защите | Страница или API поверх базы | [showcase.md](showcase.md) |

Список тем: [themes.md](themes.md). Формат файлов `demo/*.sql`: [scenarios.md](scenarios.md).

Лаба N выдаётся на встрече N и сдаётся на встрече N+1.

## Что установить

| Программа | Для чего |
| --- | --- |
| Docker Desktop (Windows, macOS) или Docker Engine (Linux) | Запуск базы командой `docker compose up -d` |
| Python 3.10 или новее | Чекер `dbcheck` |
| Git и аккаунт GitHub | Сдача лаб через Pull Request |

Установка чекера:

```bash
pipx install git+https://github.com/bozhedom/dbcheck@v1
dbcheck --version
```

Если pipx не установлен: `pip install --user git+https://github.com/bozhedom/dbcheck@v1`.

Отдельный клиент для базы ставить не нужно: вся работа с базой идёт через `psql`, он уже есть внутри контейнера с PostgreSQL.

## Первый запуск

1. Создайте репозиторий из этого шаблона кнопкой «Use this template». Имя: `db-<фамилия>-<тема>`, например `db-ivanova-cinema`.
2. Склонируйте его и создайте файл с паролями:

```bash
cp .env.example .env
docker compose up -d
```

3. Откройте `psql`:

```bash
docker compose exec db psql -U postgres -d app
```

Если в `.env` изменены `POSTGRES_USER` или `POSTGRES_DB`, подставьте свои значения.

## Работа в psql

| Команда | Что делает |
| --- | --- |
| `\dt` | Список таблиц |
| `\d имя_таблицы` | Колонки, ключи, ограничения и индексы таблицы |
| `\dv`, `\df` | Список представлений, список функций |
| `\i /demo/lab1.sql` | Выполнить файл сценария |
| `\x` | Вертикальный вывод строк, удобно для широких таблиц |
| `\timing` | Показывать время выполнения запросов |
| `\q` | Выйти |

Запрос заканчивается точкой с запятой. Папка `demo/` репозитория доступна внутри контейнера как `/demo`, поэтому сценарий можно выполнить командой `\i /demo/labN.sql`. Выполнить файл без входа в `psql`:

```bash
docker compose exec db psql -U postgres -d app -f /demo/lab1.sql
```

## Структура репозитория

```
db/            скрипты, которые создают базу; выполняются по порядку имён
  01_schema.sql  лаба 1: таблицы и ограничения
  02_seed.sql    лаба 1: тестовые данные
  10_...         лаба 3, 20_... лаба 4, 30_... лаба 5
demo/          сценарии для показа: lab1.sql ... lab5.sql, race.sql, race_fixed.sql
docs/          задания лаб
dbcheck.toml   настройки чекера
.env.example   образец файла с паролями
```

Каждая лаба добавляет в `db/` новые файлы. Старые файлы не удаляются, база растёт слоями.

**Важно.** Скрипты из `db/` выполняются только при первом запуске, пока база пустая. После изменения любого скрипта базу нужно пересоздать:

```bash
docker compose down -v && docker compose up -d
```

Всё, что создано руками в `psql` и не записано в `db/`, после пересоздания пропадёт. Засчитывается только то, что создаётся скриптами.

## Как сдать лабу

1. Создайте ветку для лабы от `main`:

```bash
git switch main && git pull
git switch -c lab-2
```

2. Выполните задание: скрипты в `db/`, сценарий `demo/labN.sql`, нужные разделы в `README.md`.
3. Проверьте себя чекером (см. ниже).
4. До 23:59 накануне занятия отправьте ветку и откройте Pull Request `lab-N` в `main`:

```bash
git add .
git commit -m "Лаба 2: запросы"
git push -u origin lab-2
```

На GitHub нажмите «Compare & pull request». В описании PR отметьте выполненные пункты чек-листа.

5. На занятии:
   - запустите базу: `docker compose up -d`;
   - покажите работу так, как написано в разделе «Сдача» задания лабы;
   - ответьте на вопрос из списка в конце задания.

После приёма PR вливается в `main`, следующая лаба начинается от обновлённого `main`.

## Как проверить себя

Из папки репозитория, когда база запущена:

```bash
dbcheck --lab 2               # шесть пунктов лабы
dbcheck --lab 2 --stars       # плюс задания со звёздочками
dbcheck --lab 2 --fresh       # то же на базе, пересозданной с нуля
dbcheck run demo/lab2.sql     # сценарий по шагам
```

Что значат значки:

| Значок | Значение |
| --- | --- |
| ✓ | Пункт выполнен |
| ✗ | Пункт не выполнен, рядом написана причина |
| 👁 | Чекер проверил то, что мог, остальное смотрит преподаватель |
| ⚠ | Предупреждение, на баллы не влияет |

После открытия PR GitHub сам поднимает базу из репозитория на чистой машине и запускает чекер. Результат виден в PR: зелёная галочка или красный крестик, подробности во вкладке Checks. Красный крестик обычно означает, что база не создаётся из `db/`: что-то сделано руками и не записано в скрипты.

## Баллы

| Что | Максимум |
| --- | --- |
| Посещение | 8 (по 1 за встречу) |
| Лабы | 60 (5 лаб по 12 баллов) |
| «Своя игра» | 10 |
| Защита проекта | 22 |

Оценка: 86-100 баллов «отлично», 76-85 «хорошо», 61-75 «удовлетворительно». Без заданий со звёздочками можно набрать не больше 80 баллов.

Одна лаба:

| Часть | Баллы |
| --- | --- |
| Чек-лист, 6 пунктов | 6 |
| Ответ на вопрос | 2 |
| ★ | 2 |
| ★★ | 2 |

Лаба принята, если выполнено не меньше 4 пунктов чек-листа. Задания со звёздочками проверяются только у принятой лабы.

## Сроки

- Срок сдачи: открытый Pull Request до 23:59 накануне занятия. Время открытия PR записывает GitHub. Пустой PR не считается.
- Если не успели сдать на занятии из-за очереди, лаба принимается на следующем занятии без потери баллов.
- PR открыт после срока или лаба сдаётся повторно: засчитывается только чек-лист и вопрос, до 8 баллов.
- Все долги нужно закрыть до встречи 7.
- Для допуска к защите должны быть приняты лабы 1-3.

## Правила

- ИИ хороший инструмент для обучения: с ним удобно разбирать теорию, запросы и ошибки. Рекомендуется пользоваться им при выполнении лаб и при этом понимать, что происходит в вашей базе и запросах.
- Не принятую лабу можно доработать и сдать на следующем занятии.
