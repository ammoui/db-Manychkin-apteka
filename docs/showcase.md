# Витрина к защите

Витрина это страница или API поверх вашей базы. Отдельно она не оценивается, но влияет на критерий защиты «Работает»: 8 баллов, если демонстрация идёт через витрину, 4 балла, если только через SQL-клиент.

Вся логика остаётся в базе: представления и функции из лаб 3 и 4. Витрина только показывает данные и вызывает функции.

## Варианты

| Вариант | Что это | Код |
| --- | --- | --- |
| Без кода | PostgREST строит REST API прямо по схеме: представление доступно как `GET /v_orders`, функция как `POST /rpc/place_order`. Для действий Swagger UI, для графиков Metabase или Grafana | Не нужен |
| Одна страница | HTML-страница поверх PostgREST: список, форма, график | Один файл |
| Свой бэкенд | Небольшой сервер на любом языке и страница | Любой объём |

## Требования

1. Витрина подключается к базе под ролями `app_reader` и `app_writer` из лабы 4, а не под суперпользователем.
2. Данные читаются только из представлений, изменяются только через функции. Своей бизнес-логики в витрине нет.
3. Есть хотя бы одно действие пользователя, которое вызывает бизнес-операцию темы.
4. Есть хотя бы один отчёт или график из представления, который обновляется после действия.
5. Витрина запускается вместе с базой командой `docker compose up`.

## PostgREST

Добавьте в `docker-compose.yml`:

```yaml
  api:
    image: postgrest/postgrest:v12.2.3
    environment:
      PGRST_DB_URI: postgres://app_writer:${APP_WRITER_PASSWORD}@db:5432/${POSTGRES_DB}
      PGRST_DB_SCHEMAS: public
      PGRST_DB_ANON_ROLE: app_writer
      PGRST_OPENAPI_SERVER_PROXY_URI: http://localhost:3001
    ports: ["3001:3000"]
    depends_on:
      db:
        condition: service_healthy

  swagger:
    image: swaggerapi/swagger-ui
    environment:
      API_URL: http://localhost:3001/
    ports: ["8081:8080"]
```

Проверка:

```bash
docker compose up -d
curl 'localhost:3001/v_orders?status=eq.new&limit=5'
curl -X POST localhost:3001/rpc/place_order -H 'Content-Type: application/json' -d '{"p_customer": 1}'
```

Ошибку триггера (`RAISE EXCEPTION`) PostgREST возвращает клиенту в виде `{"code":"P0001","message":"..."}`. Выведите её текст на странице: так видно, что правило проверяет база.

Страницу можно положить в `showcase/index.html` и раздавать через nginx в том же compose:

```yaml
  web:
    image: nginx:alpine
    volumes: ["./showcase:/usr/share/nginx/html:ro"]
    ports: ["8080:80"]
```

## Защита

Выступление 5 минут, не больше 7 слайдов:

1. Название проекта и одна фраза о нём.
2. Какую задачу решает база и для кого.
3. ER-диаграмма: таблицы, связи, где проверяется бизнес-правило.
4. Демонстрация через витрину: действие пользователя, срабатывание функции или триггера, обновлённый отчёт.
5. Лучшее в базе: интересный запрос, триггер или ускорение запроса индексом с цифрами.
6. Что было сложнее всего и чему научились.
7. Как проект можно развить.

Для допуска к защите должны быть приняты лабы 1-3.
