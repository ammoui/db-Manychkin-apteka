# Формат сценариев demo/*.sql

Сценарий это обычный SQL-файл. Его можно выполнить в `psql` целиком (`\i /demo/lab1.sql`) или по одному запросу. Чекер читает в нём два вида комментариев: начало шага и ожидаемый ответ базы.

```sql
-- 3. Отрицательная цена билета: ошибка CHECK
-- expect: error check
INSERT INTO tickets (session_id, seat_id, price) VALUES (1, 1, -100);
```

Первая строка: номер шага и что он показывает. Вторая: что должна ответить база. Дальше сам запрос.

Запуск: `dbcheck run demo/lab1.sql`. Чекер выполнит шаги по порядку, покажет ответ базы и отметит каждое ожидание знаком ✓ или ✗.

## Правила выполнения

- Файл без `BEGIN`, `COMMIT`, `ROLLBACK` выполняется в одной транзакции, которая в конце откатывается. База не меняется, файл можно запускать сколько угодно раз.
- Файл с `BEGIN`, `COMMIT` или `ROLLBACK` выполняется как в psql: команда за командой, изменения сохраняются. Чтобы показать изменение и не испортить данные, оберните его в `BEGIN; ... ROLLBACK;`.
- В шаге может быть несколько запросов. Ожидание проверяется по последнему запросу, который вернул строки.
- Шаг без `expect` должен выполниться без ошибки.
- Команды psql (`\d`, `\dt`) чекер пропускает.

## Ожидания

| Запись | Значение |
| --- | --- |
| `-- expect: ok` | Без ошибки (так же работает шаг без `expect`) |
| `-- expect: rows` | Вернулась хотя бы одна строка |
| `-- expect: rows 6` | Ровно 6 строк. Для `INSERT`, `UPDATE`, `DELETE` без `RETURNING`: изменено 6 строк |
| `-- expect: rows >= 10` | 10 строк или больше |
| `-- expect: value 42` | Первая колонка первой строки равна 42 |
| `-- expect: true`, `-- expect: false` | Первая колонка первой строки равна `true` или `false` |
| `-- expect: same 1` | Результат совпадает с результатом шага 1 (данные не изменились) |
| `-- expect: error` | Любая ошибка |
| `-- expect: error unique` | Ошибка определённого вида, список ниже |
| `-- expect: error "не больше 3"` | В тексте ошибки есть эта фраза |
| `-- expect: plan seq` | В выводе `EXPLAIN` есть `Seq Scan` |
| `-- expect: plan index` | Любое сканирование по индексу |
| `-- expect: plan only` | `Index Only Scan` |
| `-- expect: plan bitmap` | `Bitmap Heap Scan` |
| `-- expect: plan tickets_session_idx` | План использует индекс с этим именем |
| `-- expect: blocked` | Шаг ждал блокировку (только в сценариях с окнами) |

Виды ошибок:

| Запись | Код | Когда |
| --- | --- | --- |
| `unique` | 23505 | Повтор уникального значения |
| `check` | 23514 | Нарушение `CHECK` |
| `fk` | 23503 | Ссылка на несуществующую строку |
| `notnull` | 23502 | Пустое значение в обязательной колонке |
| `raise` | P0001 | `RAISE EXCEPTION` в функции или триггере |
| `permission` | 42501 | Нет прав |
| `deadlock` | 40P01 | Взаимоблокировка |
| `serialization` | 40001 | Конфликт на уровне `SERIALIZABLE` или `REPEATABLE READ` |

Вместо вида можно указать любой пятизначный код: `-- expect: error 23505`.

У шага может быть несколько ожиданий, каждое на своей строке. Например, `error fk` и `value 1`, если после ошибки идёт `ROLLBACK TO SAVEPOINT` и проверка.

## Сценарии с двумя окнами (лаба 4)

Для гонок, изоляции и взаимоблокировки вместо номера шага пишется имя окна. Чекер открывает отдельное подключение для каждого окна и выполняет шаги строго в порядке файла. Если шаг ждёт блокировку дольше 2 секунд, чекер отмечает его «⏳ ждёт», переходит к следующему шагу и покажет результат, когда блокировка снимется.

| Метка | Что это |
| --- | --- |
| `-- [setup]` | Подготовка данных в отдельном подключении до начала. Удаляет остатки прошлого запуска |
| `-- [A]`, `-- [B]` | Шаги окна A и окна B |
| `-- [check]` | Проверка в отдельном подключении после всех окон. Возвращает один `boolean`: `true`, если правило соблюдено |
| `-- [cleanup]` | Уборка. Выполняется всегда, даже если что-то упало |

Окна фиксируют свои изменения (`COMMIT`), поэтому `[setup]` создаёт данные заново, а `[cleanup]` удаляет их. Пример гонки: [lab-4.md](lab-4.md).
