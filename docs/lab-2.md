# Лаба 2. Запросы к своим данным

**Цель:** научиться получать из базы ответы на вопросы по своей теме.

**Срок:** Pull Request `lab-2` в `main` до 23:59 накануне встречи 3.

## Теория

**Порядок выполнения SELECT.** Запрос пишется в одном порядке, а выполняется в другом:

| Порядок | Часть | Что делает |
| --- | --- | --- |
| 1 | `FROM`, `JOIN` | Берёт таблицы и соединяет их |
| 2 | `WHERE` | Отбрасывает строки по условию |
| 3 | `GROUP BY` | Собирает строки в группы |
| 4 | `HAVING` | Отбрасывает группы по условию |
| 5 | `SELECT` | Вычисляет столбцы результата |
| 6 | `ORDER BY` | Сортирует |
| 7 | `LIMIT` | Оставляет первые N строк |

Поэтому псевдоним из `SELECT` нельзя использовать в `WHERE`: на этапе `WHERE` его ещё нет.

**JOIN** соединяет строки двух таблиц по условию:

- `INNER JOIN` оставляет только строки, у которых нашлась пара;
- `LEFT JOIN` оставляет все строки левой таблицы; если пары нет, столбцы правой таблицы равны `NULL`.

«Сироты» (строки без пары) ищутся так:

```sql
SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;
```

**GROUP BY и агрегаты.** `GROUP BY` собирает строки с одинаковым значением в группу, агрегатная функция считает одно значение на группу: `count`, `sum`, `avg`, `min`, `max`. `WHERE` фильтрует строки до группировки, `HAVING` фильтрует группы после неё.

**NULL** означает «значение неизвестно». Любое сравнение с `NULL` даёт `NULL`, а не `true`, поэтому `WHERE x = NULL` ничего не находит. Правильно: `WHERE x IS NULL`. `count(*)` считает все строки, `count(колонка)` только строки, где колонка не `NULL`.

**Подзапрос** это запрос внутри другого запроса:

```sql
SELECT name FROM films WHERE id IN (SELECT film_id FROM sessions WHERE starts_at > now());
```

**CTE (`WITH`)** даёт имя промежуточному результату и делает длинный запрос читаемым:

```sql
WITH sold AS (SELECT session_id, count(*) AS n FROM tickets GROUP BY session_id)
SELECT s.id, sold.n FROM sessions s JOIN sold ON sold.session_id = s.id;
```

**Оконные функции** считают значение по группе строк, но, в отличие от `GROUP BY`, не схлопывают строки: `ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC)` нумерует товары внутри каждой категории. Ещё примеры: `RANK()`, `SUM(...) OVER (ORDER BY ...)` для накопительной суммы, `LAG(...)` для значения из предыдущей строки.

## Что сделать

`demo/lab2.sql`: 12 пронумерованных запросов в формате [сценария](scenarios.md). Над каждым запросом в комментарии вопрос обычным языком. Запросы, которые меняют данные, оборачиваются в `BEGIN; ... ROLLBACK;`: так видно состояние до и после, а данные не портятся.

```sql
-- 5. Какие клиенты ни разу не делали заказ?
SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;

-- 11. Билеты на вечерние сеансы дорожают на 10%: средняя цена до и после
BEGIN;
SELECT avg(price) AS before FROM tickets t JOIN sessions s ON s.id = t.session_id WHERE s.starts_at::time >= '18:00';
UPDATE tickets SET price = price * 1.1 WHERE session_id IN (SELECT id FROM sessions WHERE starts_at::time >= '18:00');
SELECT avg(price) AS after FROM tickets t JOIN sessions s ON s.id = t.session_id WHERE s.starts_at::time >= '18:00';
ROLLBACK;
```

## Чек-лист (6 баллов)

| № | Пункт | Что нужно для зачёта |
| --- | --- | --- |
| 1 | `JOIN` | Не меньше 3 запросов с `JOIN`, в одном из них соединяются 3 или больше таблиц |
| 2 | Группировка | Не меньше 2 запросов с `GROUP BY` и агрегатной функцией, в одном из них есть `HAVING` |
| 3 | «Сироты» | Запрос с `LEFT JOIN` и `IS NULL`, результат не пустой. Если сирот в данных нет, добавьте их в `02_seed.sql` |
| 4 | Подзапросы | Не меньше 2 запросов с подзапросом (`IN`, `EXISTS`, скалярный или в `FROM`). Определение CTE подзапросом не считается |
| 5 | Изменение данных | Есть `INSERT`, `UPDATE` и `DELETE`. У `UPDATE` и `DELETE` есть `WHERE`, каждый меняет хотя бы одну строку, рядом `SELECT` до и после |
| 6 | Все 12 запросов работают | Не меньше 12 шагов, ни одной ошибки, каждый `SELECT` возвращает строки, результат отвечает на вопрос из комментария |

## Подсказки

- `NOT IN (подзапрос)` ничего не вернёт, если в подзапросе есть `NULL`. Надёжнее `NOT EXISTS`.
- Условие на правую таблицу после `LEFT JOIN` пишется в `ON`, а не в `WHERE`. Иначе строки без пары отбросятся, и `LEFT JOIN` станет обычным `JOIN`.
- Группировать лучше по `id`, а не по имени: два клиента с одинаковым именем иначе попадут в одну группу.
- Коррелированный подзапрос (ссылается на внешний запрос) выполняется для каждой строки. На большой таблице в лабе 5 это будет медленно.
